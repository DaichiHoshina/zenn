## AI が書いた日本語、そのまま人に渡せますか

> 「日本語がおかしい」

レビューで、**こう指摘されることが多かったです。**

PR の本文や設計書は、Claude Code に書いてもらうことが増えていました。

読み返すと、「本機能は」「効率的に」のような、**どこかで見たような言い回し**が混ざっています。

そこで、NG 語の辞書と文の組み立ての検査で日本語の文書を点検して書き換える、jp-lint というスキルを作りました！

https://github.com/DaichiHoshina/jp-lint

## jp-lint とは

:::message
書き終えた日本語の文書を、NG 語辞書と文の組み立ての検査で点検して書き換える、**AI エージェント向けのスキル**です。
:::

名前には、**正しい日本語を出力したい**という思いを込めています。

想定しているのは、次のような現場です。

- PR の本文や設計書の下書きを、AI に書いてもらっている
- チームの人が読む文書を、**読み手の負荷が少ない日本語**にそろえたい
- Claude Code・Cursor・Codex など、複数のエージェントを使い分けている

困っていたことと、その対応が以下になります。

| 困りごと | jp-lint での対応 |
|---|---|
| 「効率的に」「本機能は」のような**AI っぽい言い回し**が混ざる | 言い回しを分類ごとに辞書にして、スクリプトで検出する |
| 「出す」「見る」のように、**何をしたか分からない動詞**が多い | 意味の広い動詞を辞書に入れ、実際の操作を表す動詞への言い換えの方向を辞書に書いておく |
| 語だけを置き換えると、**前後の文がちぐはぐ**になる | 検出した語を含む文を単位に書き換え、識別子や引用への誤検出は理由を付けて見送る |
| 辞書の語が無くても、**文の順番が分かりにくい** | 対処から始まる文や、離れた所を指す「この」「上の」を、辞書と別に点検する |

## textlint との違い

**日本語の文章の検査では、textlint が定番です。**

AI っぽい書き方を検出するルール集 (`textlint-rule-preset-ai-writing`) もあり、MCP サーバとして Claude Code から呼ぶこともできます。

| 項目 | textlint + ai-writing | jp-lint |
|---|---|---|
| 導入 | npm でインストールし、`.textlintrc` に設定する | リポジトリを clone して `scripts/install.sh` を実行する |
| 動く環境 | Node.js | bash 4 以上 |
| 検出する仕組み | ルールごとのプログラム | 分類ごとの NG 語辞書と、文の組み立ての検査 |
| 書き換えの前に読むもの | 検出結果のメッセージ | 検出結果と、同梱の文章の規範 (共通原則と、文書の種類ごとの書き方) |

違いは最後の行、**書き換えの前に文章の規範を読むこと**です。

実は jp-lint を作る前は、textlint を使っていました。
ただ、それでも自分の文章は完璧な日本語にはなりませんでした。

結局、**自分の目で読んで、禁止語を登録していくしかない**、と。
その辞書と規範をまとめて持ち運べるようにしたのが jp-lint です。

## 使い方

| 順番 | やること | コマンド・頼み方 | 詳細 |
|---|---|---|---|
| 1 | 点検を頼む | 「この文書を点検して」 | エージェントが `SKILL.md` の手順で検査から書き換えまで進める |
| 2 | スクリプトだけ使う | `bash skills/jp-lint/scripts/jp-quality-lint.sh 対象のファイル` | 辞書と文の組み立ての検査結果だけを表示する |
| 3 | 厳しめに検査する | `--strict` を付ける | 荒い比喩語と、「確認済」のような無理やりの短縮も検出する |

エージェントは検査のあと、次の順で進めます。

1. 文書の種類に合う規範を読む (PR 本文・Design Doc・issue・長文)
2. 検出された語ごとに前後の文を読み、書き換えるか見送るかを決める
3. 文の組み立てと、外向きの文書なら主張の大きさを点検する
4. もう一度検査して、残った指摘が見送り分だけになったことを確認する

:::message alert
目的は、**書き手の意味を変えずに、読み手の負荷を下げること**です。
:::

事実・時制・因果関係・書き手の評価が変わる書き換えは、元の文に戻して見送りにします。

## こだわったところ

### 1. 検出はスクリプト、書き換えは文脈を読んでから

辞書は部分一致で検査するので、検出は速いけど誤検出もあります。

なので、検出した語を一括で置き換えることはしません。

たとえばこの文を検査すると、

```text
本機能は、ログの集計を効率的に行うことができます。
まず、設定ファイルを読み込んで、対象の行を拾います。
念のため、エラーが出た場合はリトライする可能性があります。
```

こう返ってきます。

```text
[block] AI定型語: 効率的に, 本機能は
[block] AI段取り定型 (block): まず
[block] ヘッジ濫用 (block): 念のため
[block] 曖昧な汎用動詞 (block): 出た
[warn] 構造: 同一文末3連続: 1箇所 (ます×3) → 関連する 2 文を 1 文にまとめるか ...
```

`block` は書き換える対象、`warn` は文脈を読んで判断する対象です。

ここから先は、**検出された語を含む文を単位に書き換えます**。

| 書き換え方 | 例 |
|---|---|
| ✗ 語だけを差し替える | 本機能は効率よく処理をします |
| ○ 文ごと書き換える | 1 件あたり 200ms で処理する |

:::message
コマンド名や識別子をバッククォートで囲むと、検査の対象から外れます。辞書の語を例として引用するときも同じです。
:::

### 2. 辞書は、実際に引っかかった語から増やす

辞書の語の多くは、**自分の目で読んで、読みにくいと感じた語**です。

その都度、分類と言い換えの方向と一緒に追加しています。

部分一致の誤検出は、登録する語の形で避けています。

| 例 | 対処 |
|---|---|
| 「出す」を登録すると「検出した」にも一致する | 「を出す」「に出す」のように助詞付きで登録する |
| 「残す」の「残」1 文字は「残高」にも一致する | 「残す」「残して」「残った」のように活用形で登録する |

### 3. 辞書に無い「文の順番」も点検する

読みにくさは、語だけでは決まりません。

**辞書では検出できない型**を、スクリプトの結果とは別に点検します。

- 対処から始まる文 (「〜しているのは、〜だからです」)。状況、読み手に起きること、対処の順に書き換える
- 1 文の述語に、時点や主体が 2 つ掛かる文。2 文に分ける
- 参照先から離れた「この状態」「上の〜」。指している名詞に書き換える

漢字が 6 文字以上続く語や、同じ文末が 3 回続く文も、構造の検査で見つけます。

### 4. 自分の辞書は差分だけで管理する

検出してほしくない語は、人や現場で違います。

なので、同梱の辞書は書き換えず、**追加と除外の差分だけ**を `~/.config/jp-lint/ng-words.md` に書きます。

```markdown
## 追加
**AI定型語**: させていただきます / 〜な感じ

## 除外
**英語での業界用語 (warn-only)**: fallback
- canonical
```

同梱の辞書が更新されても、自分の変更はそのまま引き継がれます。

## 導入

リポジトリを clone して、インストール用のスクリプトを実行します。

```bash
git clone https://github.com/DaichiHoshina/jp-lint.git
cd jp-lint
scripts/install.sh                 # ~/.agents/skills と ~/.claude/skills へ配置する
scripts/install.sh cursor codex    # エージェントを指定して配置する
```

symlink で配置するので、`git pull` すれば各エージェントの jp-lint も更新されます。

配置先は、`claude` `cursor` `codex` `gemini` `copilot` `agents` から指定できます。

:::message
検査のスクリプトは bash 4 以上で動きます。macOS 標準の bash は 3.2 なので、Homebrew などで新しい bash を入れてください。
:::

**これで準備は OK です！**

あとはエージェントに「この文書を点検して」と頼むだけです。

## 使ってみてどうだったか

数字では測ってないので、ここからは個人の体感です。

### ✅ 日本語への指摘がなくなった

レビューで**日本語を指摘されることがなくなりました！**

### ✅ 自分も読みやすくなった

自分自身にとっても読みやすい日本語になりました。

そのおかげで、**AI が出力する情報が分かりやすくなりました。**

## おわりに

意外だったのは、**辞書を育てる作業に終わりがない**こと。

毎日 NG 語を登録していかないといけないので、正直ちょっと大変です。
ただ、今はレビューで「日本語がおかしい」と言われることはなくなりました。

jp-lint はまだ試作の段階で、辞書もこれから増やしていきます。

AI に書いてもらった日本語が、なんだか読みにくいと感じている人がいたら、ぜひ一度試してみて、ご意見をいただけるとうれしいです！
